# 求解結果存檔：第一版

## 已確認的需求

- 儲存已完成結果整理的決策樹，載入後直接瀏覽策略、EV、圖表與後續公共牌。
- 使用自行選擇位置的獨立 `.dpfresult` 檔案。
- 提前停止後，只要已完成 finalize，也可以儲存。
- 保留迭代次數、exploitability、累積計算時間，以及是否手動停止。
- 一起恢復 Solver 的雙方範圍、公共牌、底池、籌碼、抽水、下注尺度、donk 選項、建樹門檻與手動編輯分支。
- 新檔另外記錄執行緒數、目標 exploitability、最大迭代數；精度模式依檔案中的實際資料恢復。
- 替換未儲存的結果前，提供 Save and Continue、Discard and Continue、Cancel。
- 開檔失敗保留目前結果；取消存檔不視為已儲存。
- 不支援 Bunching；不提供恢復求解進度功能。

## 程式路徑

```text
RunSolver.vue
  └─ 完成 finalize，記錄統計與未儲存狀態

ResultFiles.vue
  └─ result-files.ts：檔案選擇、替換確認、介面狀態
       └─ invokes.ts：Tauri IPC
            └─ src-tauri/src/result_file.rs
                 └─ postflop-solver：序列化完整 PostFlopGame
```

引擎的 memo 欄位保存帶版本的 JSON 統計與結果頁所需的初始局面資料。
完整手牌範圍、下注樹與策略由引擎保存；只回傳小型 metadata 給前端，不把整棵樹經由 IPC 傳輸。

寫檔先建立同目錄暫存檔，成功寫入並同步後才替換目的檔。讀檔先解碼、驗證版本、完成狀態與 metadata，成功後才替換記憶體中的舊結果。
保留舊結果時會同時需要新舊兩份結果的記憶體。macOS 與求解畫面一致，以實體 RAM 的 70% 減去舊樹的估計用量作為載入預算；其他平台使用系統回報的可用 RAM。這是預算估計，並非記憶體配置成功的保證。
超出預算時會顯示上限；可先儲存目前結果、重新啟動 App，再開啟檔案，以免同時保留兩份樹。

載入後使用新的 resultRevision 重建結果與設定元件，清除上一份結果的節點快取。由引擎中的實際範圍與下注樹重建 Solver 設定，同步前端 Pinia 與 Rust RangeManager，因此後續建立新樹也會使用載入的範圍。
設定畫面、求解快照與結果頁分別持有公共牌陣列，避免修改設定時連帶改掉已完成結果的牌面。下注尺度會轉成一致的文字格式，語意與引擎相同，未必保留原始輸入的空格。
舊檔也能從引擎恢復局面設定；沒有記錄過執行緒數、目標精度或最大迭代數的舊檔，這三項使用預設值。載入後能研究結果或用恢復的設定建立新樹，但不支援接續舊求解的迭代狀態。

保存完整到 river 的樹，預設使用 zstd level 3 無損檔案壓縮；保留求解時選定的 32-bit／16-bit 儲存精度與策略數值。壓縮比例依局面而異，儲存和載入時需要額外的壓縮／解壓縮工作。
既有未壓縮的 `.dpfresult` 仍可直接開啟；載入後重新儲存即可轉成壓縮檔，不需要重新求解。可先另存新檔並驗證，確認後再處理舊檔。
檔案變小不代表載入後的 RAM 需求變小。求解時的 16-bit 精度模式可以另外減少記憶體與資料量，但會改變數值精度，與本次的無損檔案壓縮不同。
檔案格式同時受 App metadata 版本與引擎版本限制，不保證可在其他 solver 或未來不同引擎版本開啟。

## 自動檢查

```sh
npm run build
npm run lint
npm run test:result-files
cargo test --manifest-path src-tauri/Cargo.toml --locked --offline result_file::tests
```

前端測試使用模擬的原生檔案對話框和 IPC，涵蓋取消、儲存失敗、替換確認、連續載入與忙碌狀態。
Rust 測試使用實際引擎，驗證 flop／turn／river 起始局面及兩種精度的存取，對照根節點與 river 策略、EV、equity，並檢查壞檔、截斷檔、記憶體不足、錯誤版本及寫檔失敗時的保留行為。

## 桌面手動驗收

使用 `npm run tauri dev`：

1. 建立小型 river 局面並求解；確認 Save Result 從停用變為可用，顯示 `*`。
2. 儲存檔案，記下根節點及一個後續節點的策略與 EV。
3. 關閉並重新啟動 App，用 Open Result 載入，對照同樣節點的數值與計算統計。
   回到 Solver，確認 OOP／IP 範圍文字、權重格子、組合數、公共牌文字與選牌、下注樹設定及 Run Solver 選項都一致；修改設定中的公共牌，確認 Results 的原始牌面不受影響。
4. 另做一個 flop 局面，儲存再載入，確認可以選 turn／river，並查看圖表。
5. 提前 Stop，等待結果整理完成後儲存，確認載入後顯示 Stopped early。
6. 有未儲存結果時開另一檔：分別測試 Cancel、Discard and Continue、Save and Continue；也測試在儲存對話框按取消。
7. 選擇損毀或截斷的結果檔，確認錯誤提示出現，舊結果仍可正常瀏覽。
8. 啟用 Bunching 並完成求解，確認不能儲存，且有原因提示。
9. 檢查視窗最小尺寸、鍵盤 Tab／Escape，以及儲存／載入過程中無法操作背景畫面。

本次驗證環境沒有瀏覽器自動操作工具，原生檔案對話框與桌面完整操作仍需執行以上手動驗收。
